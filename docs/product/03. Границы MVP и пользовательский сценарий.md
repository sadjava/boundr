# 03. Границы MVP и основной пользовательский сценарий


## Границы MVP

### Внутри MVP

| # | Возможность | Статус |

| 2 | Проекты со словарями действий и объектов | ✅ Готово |

### За границей MVP (осознанно)

| Что | Почему не сейчас |
|---|---|
| Роли, команды, права доступа | Кейс явно выносит за скоуп |
| Биллинг, промышленная нагрузка | Кейс явно выносит за скоуп |
| Дашборд руководителя разметки | Ценно, но не на критическом пути; появится, когда разметчиков станет больше одного |
| Горячие клавиши, массовые операции | Ускоряют опытного пользователя, но не проверяют гипотезу |
| Видео длиннее 30 с, монтажные склейки | Вне условий кейса |
| Несколько людей в кадре | Вне условий кейса |
| Дообучение модели на правках пользователя | Сильная идея на будущее: правки — это готовый обучающий сигнал. Но это отдельный продукт |
| Интеграции с внутренними системами | Кейс явно выносит за скоуп |

**Принцип отсечения:** в MVP входит только то, без чего невозможно проверить главную
гипотезу — «проверка черновика втрое быстрее создания разметки». Всё, что делает
продукт приятнее, но не влияет на этот замер, ждёт.

## Основной пользовательский сценарий

**Актор:** разметчик данных.
**Контекст:** получил пачку из 50 роликов, нужно разметить к завтрашнему дню.
**Цель:** размеченный датасет в JSON.

| Шаг | Действие пользователя | Ответ системы | Статус |
|---|---|---|---|
| 1 | Входит в систему | Список проектов | ✅ |
| 2 | Открывает проект «Кухня-2026» со словарём из 9 действий | Список видео со статусами | ✅ |
| 3 | Загружает ролик | Файл идёт напрямую в S3, статус `UPLOADED` | ✅ |
| 4 | Нажимает «Обработать» | Задача в Redis Stream, статус `QUEUED → PROCESSING` | ✅ |
| 5 | Ждёт (до 2 мин) | Статус `COMPLETED`, таймлайн заполняется сегментами | ✅ |
| 6 | Просматривает ролик, сверяясь с таймлайном | Плеер синхронизирован с таймлайном, активный сегмент подсвечен | ✅ |
| 7 | Видит, что 3-й сегмент начался на полсекунды раньше — тянет границу | Границы обновляются, `keyframe` автоматически удерживается внутри интервала | ✅ |
| 8 | Меняет действие с `push` на `open` из списка проекта | Значение сохранено, статус разметки → `EDITED` | ✅ |
| 9 | Удаляет ложный сегмент | Сегмент исчезает с таймлайна | ✅ |
| 10 | Нажимает «Следующее видео» | Переход без возврата в список | ✅ |
| 11 | После пачки — экспортирует | JSON или CSV скачивается | ✅ |

### Где сценарий сейчас ломается

Шаг 5. Сегменты, которые увидит пользователь, приходят от пайплайна-заглушки:
структура корректна, длительность соответствует видео, но содержание синтетическое.
Все остальные шаги — боевые и проверены вручную.

Это осознанный порядок работ: мы сначала убедились, что контур приёмки работает
целиком, и только потом встраиваем в него модель. Обратный порядок — сначала модель,
потом интерфейс — оставил бы нас с хорошими эмбеддингами и без продукта.

## Ключевые продуктовые решения и их отражение в коде

Каждое продуктовое решение имеет конкретный технический след — это связь,
которую мы держим явной.

| Продуктовое решение | Техническая реализация |
|---|---|
| Пользователь никогда не начинает с пустого экрана | Разметка приходит со статусом `GENERATED`; при правке переходит в `EDITED` — видно, что человек трогал |
| Плохой черновик не должен ломать работу | `AnnotationSegment` чинит данные: клампит `keyframe` в `[start, end]`, подставляет середину, отвергает `end < start` |
| Модель может ответить мусором — это не должно терять прогон | Статусы `OK` / `SCHEMA_ERROR` / `INVALID_JSON`, сырой ответ сохраняется всегда |
| Можно сравнить разные модели на одном ролике | Таблица `inferences` с уникальным ключом `(video_id, pipeline)`, отдельная от правок пользователя |
| Работа идёт пачками, а не по одному ролику | Навигация prev/next прямо в редакторе; `neighbor_ids` на бэкенде |
| Словарь действий задаётся под задачу датасета | `action_types` и `objects` в проекте, передаются в `JobContext` ML-сервиса |
| Модель должна меняться без переписывания продукта | Абстрактный класс `Inference`, пайплайн выбирается строкой в запросе на обработку |
| Большие файлы не должны упираться в бэкенд | Presigned-URL, видео идёт браузер → S3 напрямую |
| Типы действий должны различаться взглядом на таймлайне | 7 категориальных цветов в дизайн-системе, с дублированием текстом (цвет — вторичный сигнал) |

## Критерий готовности MVP

MVP считается собранным, когда пользователь может пройти сценарий целиком
с **реальной** моделью на шаге 5, и время прохождения замерено против ручной разметки
тех же роликов.
