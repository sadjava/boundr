# Marlin fine-tuning

The pipeline is: **video + ground-truth actions → base Marlin scene and frozen
visual cache → caption target → language-only LoRA → caption inference**.

The user prompt is exactly Marlin's canonical caption prompt. Each assistant
target retains the `Scene:` paragraph generated by base Marlin during caching
and uses annotation timestamps and `action | object` text for `Events:`:

```text
Scene: [the spatial description generated by base Marlin, unchanged]

Events:
<0.14 - 3.37> open | door
<4.37 - 6.17> turn on | light
```

Labels come directly from ground truth; underscores become spaces in the training
text. The pipe separates action from object as ordinary text; labels cannot
contain it. Marlin's chat markers and assistant end token remain unchanged.
Overlapping actions stay separate. Unannotated intervals have no invented
rows, and a clip with no annotated actions retains its scene and an empty
`Events:` section. This defines the target event scope as the supplied annotations.

The full assistant response, including the preserved scene and end token, incurs
loss. User/video prompt tokens are masked. Vision, the merger, embeddings, and
output head remain frozen; LoRA trains the language decoder. Keeping a scene in
training targets does not guarantee identical generated scenes after tuning.

Validation loss selects the training checkpoint.

## Setup

Use Linux, an NVIDIA GPU with BF16 support, FFmpeg shared libraries, and `uv`.
The environment pins Python 3.11-compatible packages, CUDA 12.6 wheels, and
Marlin revision `fd111fca4fc7897876fb0d7e9df22ca5ac8ab965`.

```bash
cd finetuning
UV_CACHE_DIR="$PWD/.uv-cache" uv sync --locked --python 3.11
.venv/bin/hf auth login
```

Hugging Face login is needed only if model access is not already configured.

## Dataset preparation

```text
dataset/
  train/<source>/annotations/*.json
  train/<source>/video/*.mp4
  eval/<source>/annotations/*.json
  eval/<source>/video/*.mp4
```

Annotations contain `video_id`, positive `duration` in seconds, and `segments`
with `start`, `end`, `action`, and `object`. The annotation and MP4 share the
same filename stem. All sources use this common format; source directory names
and clip IDs are opaque identifiers. Convert source data to this layout before
running preparation.

Set the dataset root explicitly when using a worktree. Otherwise it defaults to
`../dataset` beside Boundr:

```bash
export MARLIN_DATASET_DIR=/absolute/path/to/dataset
.venv/bin/python data.py prepare --output runs/caption/prepared
```

The output contains `train.jsonl`, `val.jsonl`, and `summary.json`.
Records contain video paths, structured ground-truth events, and annotation file
hashes. Videos and source annotations are read-only.
The supplied train/eval split is retained, and shared video paths are rejected.
Choose the split before preparation to keep related clips in the appropriate
partition. The eval split supplies validation loss for checkpoint selection.

## Train

Run heavy work under `systemd-run` with explicit resource limits. From `finetuning/`:

```bash
systemd-run --user --scope -p MemoryMax=32G -p CPUQuota=400% \
  bash run_all.sh runs/caption
```

`run_all.sh [run-directory]` prepares annotations, generates scenes and caches
training targets and vision features, then trains.
Its default directory is `runs/caption`; relative paths resolve from `finetuning/`.
The launcher locks each run and rejects existing adapter directories.

Individual steps:

```bash
.venv/bin/python data.py prepare --output runs/caption/prepared
.venv/bin/python cache.py --prepared runs/caption/prepared --output runs/caption/cache
.venv/bin/python train.py --cache runs/caption/cache --output runs/caption/adapter
```

During caching, the frozen base model uses the canonical prompt and greedy decoding
to generate each scene, stopping at the `Events:` header. The same vision forward
pass supplies the cached features. The scene is stored with those features, and
ground-truth events complete the training target. The default scene budget is
1,024 tokens (`--scene-max-new-tokens`); an incomplete or malformed scene fails
caching. Generated scene descriptions can contain model inaccuracies.

The cache contains the completed targets in `train.jsonl` and `val.jsonl`, plus
`target-review.md` with up to four representative training targets per source.
Reusing a matching cache reuses its scenes as well as its vision features;
changing ground-truth events rebuilds targets without regenerating scenes.

Preprocessing uses complete clips at 2 FPS, capped at 240 frames and 25,165,824
pixels, with native video timestamps and chat formatting. The maximum sequence
length is 32,768; oversized inputs and targets fail instead of being truncated.
Matching caches can be reused with `cache.py --reuse-visual-cache PATH`.
Base weights, preprocessing, prompt, scene generation settings, and feature code
identify reusable scene/vision artifacts. Interrupted caching reuses completed
artifacts; training rejects incomplete caches.

Defaults: three epochs, BF16, LoRA rank 16/alpha 32, learning rate `1e-4`, one clip
per microbatch, four accumulation steps, and gradient checkpointing. The saved
adapter is the checkpoint with lowest validation loss. Use `train.py --help`
for overrides. A small smoke run can use a separate cache with `--limit 1` and
training with `--max-steps 2 --accumulation 1`.

Resume interrupted training with the same settings and `--resume PATH/checkpoint-N`.
To add epochs in a new run, use `--continue-from PATH/checkpoint-N --epochs 3`.
Continuation restores adapter weights and optimizer moments with a fresh schedule;
it requires the same base model, prompt, target format, and LoRA dimensions.

## Generate a caption

```bash
.venv/bin/python infer.py /path/to/clip.mp4 \
  --adapter runs/caption/adapter --output caption.json
```

Inference restores the vision tower, loads the adapter and recorded processor,
and uses the unchanged Marlin prompt. It prints the raw `Scene:` + `Events:`
response. Saved JSON includes the raw
caption, duration, and truncation status. The default generation cap is 2,048 tokens;
reaching the cap before EOS reports failure while retaining the output.

These PEFT adapters run through the standalone Transformers command.
Boundr's Compose `finetune-service` processes mock jobs, and the application's
inference queue serves Marlin through llama.cpp.

## Checks

```bash
python3 check_pipeline.py
```

The check covers prompt equality with the product, preservation of scene text,
ground-truth event replacement, overlaps, empty annotations, invalid input, and
preparation using only videos and annotations. To check that cached scenes and
ground-truth events form the supervised response with the native tokenizer,
without loading model weights:

```bash
.venv/bin/python check_pipeline.py --visual-cache /path/to/cache \
  --processor /path/to/local/Marlin-2B/snapshot
```
